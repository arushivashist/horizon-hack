Long Horizon Agents Hackathon · Sep 25, 2026

Does explicit state beat history?

We built a fake online store with weeks of on-call pages, planted problems with known causes, and let three agents with different memory designs investigate. Here is how it works and what we found so far.

How it all fits together

Every alert becomes a page. A small Liquid model clears known false alarms; everything else goes to the Claude agent, which investigates with SQL and has to name the exact deploy or config change behind the problem. A grader checks the answer against a key the agent never sees.

  • Tinybird

    Holds the store's telemetry and cuts every query off at the page time. Keeps whatever each design carries forward (summaries, notes or lessons) as a log you can replay, and records every call and score for the dashboard.

  • Liquid

    A small, cheap model in front of Claude that clears the nightly false alarms and does the end-of-day reviews, which took most of the calls in the prototype. Its test: the day-12 incident starts with the same alert name as the false alarm.

  • Nimble

    Pulls a real payment provider's incident history from its public status page, so the outside outages follow real timing and wording. Stretch goal: a live status check the agent can call mid-investigation.

  • Claude

    The investigator. It runs one of the three memory designs below, and that design is the only thing that changes between runs.

What makes it hard

Each planted problem has a delay, a decoy or a repeat that looks a little different. Remembering past pages helps; lazy pattern-matching fails.

Three ways to remember

All three agents use the same model, tools and query budget. The only difference is what each one remembers between steps and between incidents.

  • History + summaries

    One long conversation for the whole rotation: every page, query and result stays in view. When it gets too long, the agent writes itself a summary, and the summary replaces the old conversation. Most agents work this way today.

    Think of it asAn engineer who remembers everything until their head is full, then writes a recap and forgets the details.

    In testingAccurate and cheap, but its memory kept growing until each summary reset it.

  • Notebook

    Starts from a blank slate at every single step. The model sees only a short list of lessons it wrote itself, notes on the current incident, and the result of its last query, so it has to write down what each result taught it.

    Think of it asAn engineer with no memory who relies entirely on sticky notes.

    In testingTiny memory, but it forgot things mid-investigation, re-ran the same lookups and cost the most.

  • Combined

    Remembers everything within one incident, like the baseline. When the incident closes, that conversation is thrown away and only a few short lessons, each backed by a page it investigated, carry over to the next one.

    Think of it asAn engineer who focuses fully on the current incident, then jots a few notes in a runbook before moving on.

    In testingMatched the baseline's accuracy and speed while keeping about a third as much in view.

What we found

All three got every page right. The combined design matched the baseline on the repeat incident with about a third of the context, while the notebook forgot mid-investigation and cost the most.

  • The lesson that never got savedThe notebook's memory filled up with notes about the nightly false alarm, so the day-4 lesson didn't fit and was dropped.
  • Forgetting mid-investigationSeeing only its latest result, the notebook re-ran the same deploy and config lookup four times on day 12.
  • The shortcut that skipped the checkBoth memory agents learned to clear the false alarm in two queries and stopped checking config changes at 3am. In one run the baseline did check, and flagged the day-4 outage 8 hours before it hit.

Today's build

Stretch the world to 30 days and 10 incidents, run all three designs through the architecture above, and chart context size across the month: flat for the combined agent, a sawtooth for the baseline.
